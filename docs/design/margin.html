Margin and liquidation (G1): design

Superseded in part by shared-account.html: the account is now shared per book (cross margin), so liquidation is checked per bar against all pairs instead of a per-pair price level.

Status: design only, nothing implemented. Approach agreed: Nautilus style, 30x leverage for FX. Source of truth for the Nautilus behaviour: local clone 27a8e54e7 (2026-08-02).

1. Goal and non-goals

Problem. A pair's account can fall below zero and keep trading a fixed $10,000, with no check that it can afford the trade. Nine FX pairs ended below $0 (worst AUDUSD, -$2,290).

Goal. Model the account the way a margin broker and Nautilus do: a trade needs margin before it is accepted, and a position is liquidated when equity falls to the maintenance level.

Non-goals for this phase. Costs (spread, commission, swap) stay out by choice. No shared cash across pairs (each pair keeps its own account). No change to how equities (XNYS) behave. No change to sizing (fixed notional stays).

#RequirementTest

4. Use cases

UC1 Open a position under margin

Trigger: the strategy submits an entry. Main: engine computes initial margin, free margin covers it, order accepted, fills next bar. Postcondition: used margin = notional / 30.

Alternates: A1 free margin too small: order rejected with reason, no fill. A2 order only closes: accepted without a margin check. A3 flip: old margin released, new side checked.

UC2 Hold a position through losses

Trigger: price moves against the position. Main: equity falls but stays above maintenance; nothing happens.

Alternates: B1 price touches the liquidation level inside a bar: liquidation fills at the level, working orders cancelled. B2 price gaps through the level at the open: fills at the open, equity may end below maintenance or below 0. B3 the strategy's own stop-loss and the liquidation level are both in the same bar: the bar-order rule decides which fills first; the nearer one fills, the other is cancelled with the position. B4 after liquidation the strategy tries to re-enter: UC1 A1 rejects it while free margin is short.

6. Pseudocode

Typed, matches existing names. Not final code.

class MarginSpec(BaseModel, frozen):
    leverage: float = 30.0            # D2, > 1
    maintenance: float = 0.5          # D3, fraction of initial, 0 < m ≤ 1

    def initial(self, notional_usd) -> float:      return notional_usd / self.leverage
    def maintenance_margin(self, notional_usd) -> float: return self.initial(notional_usd) * self.maintenance

class ExecutionSpec(BaseModel, frozen):
    ...existing fields...
    margin: MarginSpec | None = None  # D12, None = today's behaviour

class OrderOrigin(StrEnum):
    STRATEGY, STOP_LOSS, SQUARE_OFF, LIQUIDATION   # new: LIQUIDATION

class Margin:                                      # new, owned by Context, pure arithmetic
    spec: MarginSpec
    valuation: Valuation

    def used(self, portfolio) -> float:            # D4: entry notional
        if portfolio.open is None: return 0
        return spec.initial(valuation.notional(abs(portfolio.quantity), portfolio.open.entry_price))

    def free(self, portfolio, mark) -> float:      # M3
        return max(0.0, portfolio.equity(mark) - self.used(portfolio))

    def required(self, order, portfolio, mark) -> float:   # M2, M4, D10
        opening = opening_quantity(order, portfolio.quantity)   # 0 for pure closes
        if opening == 0 and order.notional is None: return 0
        notional = order.notional if order.notional is not None else valuation.notional(opening, mark)
        return spec.initial(notional)

    def liquidation_price(self, portfolio) -> float | None:     # D5, solve equity(L) = maintenance
        if portfolio.open is None: return None
        q, e, cash = portfolio.quantity, portfolio.open.entry_price, portfolio.cash
        m = spec.maintenance_margin(valuation.notional(abs(q), e))
        k = q * valuation.instrument.multiplier
        match valuation.conversion:
            case IDENTITY:   L = e - (cash - m) / k                 # cash + k(L - e) = m
            case RECIPROCAL: d = cash - m + k                       # cash + k(L - e)/L = m
                             L = k * e / d if d > 0 else None
        return L if L is not None and L > 0 else None             # None: level unreachable
